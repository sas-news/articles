## Gitとは
Gitはソースコードのバージョン管理に使用するツールといわれています。
といってもよくわからないと思うので、今の皆さんが使用する目的を簡潔に説明すると以下のようです。
- バックアップ
- 共同開発

### バックアップ
皆さんはバックアップをとっていますか？
そのPCが突然壊れたらコードはどうするんですか？

そして、ブラウザベースで書いている皆さん。おしまいです。そのサイトがなくなったらもうアクセスできません。ブラウザが消えたら全て飛びます。

しかしGitHubにコードをアップロードしておけば、**GitHubがなくならない限り**ソースコードは保存されます。もちろん皆さんのPC内にもコードがある状態になるのでリスクは格段と低くなります。

バックアップを作成する通常のツールと違うのは、テキストデータを主にしているため1ファイルあたり100MBの制限があるということと、今までの変更内容も全て保存されていくことです。

全ての変更が保存されるため、「あの時のコードに戻したいなー」といったことが簡単に可能になります。
:::message
こういった恩恵があるため、使わなくなったコードをコメントアウトする行為はする必要がなくなります。
しないよね？
:::

### 共同開発
プログラマーを極めると他の人とコーディングする機会が増えてきます。そんな時にGitが存在せず、USBでファイル交換をしていたらファイル名や更新箇所の擦り合わせなど大変なことになります。
![](https://storage.googleapis.com/zenn-user-upload/fcf8fb2338c5-20240914.png)
こんなふうにはしたくないですよね。

Gitを使うとコードの変更箇所を記録できます。何行目にこういうコードを追加したとか、削除したとかが保存されるため、同時に一つのファイルを編集しても**編集した行が違えば**そのまま自動でくっついてくれます。同じ行を触った場合のことは後ほど説明します。

## コミット
:::message
新しいコードを追加した時、変更を加えていない行にも「変更された」表示が出てしまう場合があります。
```diff python
-print("hello")
+print("hello")
+print("world")
```
原因は複数考えられますが、多い理由として最終行の改行があります。
プログラムをするとき改行をすると「改行コード」というものが追加されます。改行コードがLFの場合は改行をすると`\n`というテキストが追加されます。そのためGit上では変更があったと判定されます。
```diff python
-print("hello")
+print("hello")\n
+print("world")
```
こういう問題があるため、コードの最終行は何も書いていない行を作っておくといいです。
:::

## プルリクエストとマージ

### 強制マージ
VSCodeの機能を使って強制的(プルリクを作らず)にマージすることができます。マージはコードに多くの変更を促すため、なるべくプルリクを出したほうがいいです。
## 特殊なファイル
### .gitignore
GitHubに送信したくないファイルがある場合は`.gitignore`に記載しましょう。
```
test/*
test.py
```
具体的には、.envやbuild/のようなGitHubに公開してはいけない、もしくは公開する必要がないファイル、フォルダを登録しておきましょう。
### README.md
他の人が見た時になんのリポジトリかわかるように`README`を書いておくことがマナーです。

このファイルは名前の通り最初に読んでほしい内容を書きます。またGitHubではリポジトリのトップに表示されるので、書いておくと印象がいいです。

具体的にどの程度書くかは自分で決めてください。公開されているリポジトリの中にはプロジェクト名だけのものから環境構築からデプロイまですべて解説されているものもあります。

チーム内で使用する分には、いつの大会のもので誰が作っているか分かればいいです。
### LICENSE
おまけ程度に`LICENSE`の説明をします。ライセンスが必要になるのはOSS(オープンソースソフトウェア)として公開する場合です。

GitHubでは誰でもアクセスできる`Public`としてリポジトリを公開できますが、ライセンスがないと他の人が編集できません。これはGitHubのシステムの話ではなく法的な話で、ライセンスがついていないリポジトリを改造して公開すると違法行為になってしまいます。
GitHubに公開したソフトウェアは誰でも使っていいことを示すためにライセンスをつけるのが一般的です。

実際にライセンスをつける方法ですが、これはGitHubに便利な機能がついています。
GitHubのサイトからファイルを作成し、そのファイル名を`LICENSE`にすると下に`Choose a license template`と表示されるのでそれを押してください。

そこに並んでいるものの中からライセンスをつけます。もちろん、ライセンスは自分でイチから書くこともできますが、そんな手間をかける必要はないわけです。
よく使われているのは`MIT LICENSE`で、要するに「煮るなり焼くなり好きにしてね。責任は負わないよ！あと著作者の名前は書いてね。」といった内容です。その他のライセンスは使いたい時に自分で調べてみましょう。
